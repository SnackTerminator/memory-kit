# 可定制面（CUSTOMIZE）

> **原则**：**只暴露清单内的可定制项**；**清单外一律走"议题"、禁私改**（否则升级必冲突）。

---

## 一、可定制面清单（**全部就这些**）

### 1.1 配置文件 `kit.conf`（放在你的**库根**）

```ini
# memory-kit 配置（可定制面）—— 改这里＝显式调参，须留痕
L2_MAX_ITEMS = 300       # L2 条目总数上限
L2_MAX_CHARS = 10000     # 单个 L2 条目的体积上限（字符）
TTL_DEFAULT_DAYS = 180   # 未标 ttl 时，按此天数判过期（0＝不判）
```

**规则**：
- **缺省即用内置默认**（闸会明示"上限来源：默认值"）；
- **改了要留痕**（在 `CHANGELOG` 或你自己的日志里记一句"因何调高"）；
- ⚠️ **机器永远不自动调高上限** —— 触顶时它只会让你**降冷或合并**；**只有你能改配置**。

### 1.2 条目元数据（写在每个 L2 条目的 frontmatter）

| 字段 | 可定制？ | 说明 |
|---|---|---|
| `ttl` | ✅ | `permanent` / `YYYY-MM-DD` / `<n>d` |
| `family` | ✅ | 族名 —— 决定**去重／蒸馏候选**怎么分组 |
| `created` | ✅ | 配合 `<n>d` 用 |
| `admit.*` | ◐ | 三问的**答案**由你写；**三问本身不可改** |
| `layer` | ❌ | 层级由规范定义 |

## 二、**不可改**的部分（内核不变量）

| 不可改 | 为什么 |
|---|---|
| **四层结构**（L0–L3 的定义与边界） | 改了就不是同一套体系；要改请走"议题" |
| **四道闸的语义**（入口／容量／寿命／合并） | 各自对应一类真问题，缺一即漏 |
| **四种动作的留痕要求**（追加／修订／蒸馏／遗忘） | 「**永不静默删**」是底线 |
| **入口件（`AGENTS.md` / `MANIFEST.md`）的读序与优先级** | 换宿主不改字＝北极星① 的落点 |
| **`AGENTS.md` 只写指针** | 一旦往里塞内容，它就不再宿主无关 |

## 三、想加新能力？走"议题"，别私改

**做法**：在你自己库里开一个 `议题.md`，写清：
1. **触发它的真实场景**（**有实例吗？** 没有实例 ⇒ 先别加）
2. 现在的做法为什么不够
3. 你期望的改变
4. 它**会不会影响升级兼容**

> **判据**：**禁为建而建** —— 先问「**抽掉它，干活时会不会出乱子？**」不会 ⇒ 不加。

## 四、几组常见的"想改"与建议

| 你想 | 建议 |
|---|---|
| 把 L2 上限调很大 | **先别** —— 上限的意义是**逼你去蒸馏**；确要调，写清理由再调 |
| 给条目加自定义字段 | 可以（frontmatter 是 YAML 子集，**只支持一层缩进**）；但**闸只认上表字段**，自定义字段不参与判定 |
| 换掉 Markdown 真源 | **不建议** —— 那等于放弃"你能看见、能带走" |
| 让机器自动整理记忆 | **不建议** —— 四种动作**必须留痕**；自动改库会让"为什么变成现在这样"不可追 |
