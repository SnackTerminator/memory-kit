# 支持边界与反馈（SUPPORT）

> **自助优先**。本文说清：**支持到哪、不支持到哪、怎么报**。

---

## 一、支持到哪（Support Scope）

| 支持 | 说明 |
|---|---|
| ✅ **套件自身缺陷** | 脚本报错、自检红、文档与行为不符 |
| ✅ **接入问题** | 按 `adapters/CONTRACT.md` 适配时卡住（**先附你的适配记录**） |
| ✅ **规范理解** | 四层／四闸／四种动作的含义与判据 |
| ⚠️ **你的宿主产品本身** | 只作**方向性**提示；具体问题问该产品官方 |
| ⚠️ **你的数据** | **我方看不到你的 I 层** —— 数据相关问题需你**自行脱敏后**复述现象 |

---

## 二、**不支持**哪些（明确排除 · 防范围蔓延）

1. **不会装软件** —— 前置条件就是"你已在用某个 AI Agent 产品"；本套件**不做保姆式安装引导**；
2. **要我方托管你的记忆** —— 本套件**不做托管**，记忆始终在你自己的文件里；
3. **商业级多租户／合规审计** —— 那不是本套件；
4. **帮你修宿主产品** —— 那是宿主厂商的事；
5. **承诺"记忆一定不出错"** —— 本套件提供**机制与判据**，不提供**内容正确性担保**。

---

## 三、报缺陷：**反馈四件套**（缺一难查）

**报到哪里（二选一）**：

- **GitHub Issues**（推荐 —— 公开、可检索、别人也帮得上）：`https://github.com/SnackTerminator/memory-kit/issues`
- **邮箱**：`dudwr527318@163.com`（不方便公开时用）

> ⚠️ **两条通道都请先按 §四 脱敏** —— 尤其往邮箱发时，**不要把没脱敏的库内容贴进来**。

1. **你敲的完整命令**（原样复制，别改写）
2. **完整报错原文**（**别截图、别只描述**；文字才能检索）
3. **环境**：`python --version` ＋ 操作系统 ＋ 你的宿主产品名
4. **自检输出**：
   ```bash
   python tests/gates_selftest.py --quiet
   python install/verify.py --root <你的库>
   ```

**加分项**：能**最小复现**的目录结构（**必须先脱敏**）。

## 四、★ 报缺陷前请先**脱敏**

**你的记忆库含私人内容** —— 报缺陷时**只发结构、不发内容**：

| 可发 | 不可发 |
|---|---|
| 文件**名**与目录结构 | 身份件**正文** |
| **报错原文**（含路径时把用户名替换为 `<user>`） | 画像／经验条目的**内容** |
| 四闸的**判据输出行** | 任何**密钥／令牌／账号** |

> **我方永远看不到你的 I 层**（这是设计红线，不是承诺话术）。

---

## 五、已知限制（诚实声明）

1. **尚未在多个异构宿主上做完整实测**（适配契约成件，但适配器集未全量落）；
2. **四闸的"容量上限"默认值是保守估计**，不是调优结论；
3. **判据②（n-gram 交叉）** —— **现行口径见 `spec/零私人内容判据.md` §7.6：v2 起恢复硬判（FAIL）**；**旧述「仅作可疑信号」已废**（对照物："与参照系同源"场景的鉴别力问题已在度量口径中处理）；
4. **无 GUI**：所有操作走命令行 ＋ 编辑器。

---

## 六、设计立场（为什么限制这么多）

> **本套件的目的不是"什么都替你干"，而是"让记忆真正属于你"** ——
> 所以它**不托管、不上云、不要密钥、不绑宿主**；代价是**你必须能跑一条命令、能编辑一个文件**。
