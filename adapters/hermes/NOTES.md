# Hermes 适配要点（NOTES）

**宿主**：Nous Research **Hermes Agent**（**安装目录因机而异 ⇒ 取法**：跑 `hermes --version`，读其 `Install directory` 行）
**形态**：**裸库直读**（`adapterShape: bare-read`）—— **零改造**，不写插件、不动其配置

---

## 一、怎么接（给用户）

告诉它一句话即可：

```
读 <你的库目录>/AGENTS.md，按它指向的顺序读取。
```

要它**复述读序**来验收：应输出 6 行（`SOUL → USER → IDENTITY → MEMORY → 会话速读包 → 当日通告`）。

## 二、本宿主的实操要点

| 项 | 说明 |
|---|---|
| **非交互调用** | `hermes -z "<prompt>"` —— **一条命令问一句**，适合脚本化验证 |
| **工作目录** | 用 `--in <DIR>` 指定；**传路径一律用绝对路径** |
| **自带记忆** | 它有**自己的** `SOUL.md` 与 `hermes-agent/AGENTS.md` ⇒ **共存不抢位**：只让它**多读一个入口件**，**不替换、不修改**其原有件 |
| **无根变量** | 未依赖其提供根变量 ⇒ 走契约 **§三-4 降级约定（载体优先）**：① 环境变量 `MEMORY_KIT_DATA` ／ `memory-kit.conf` → ② **用户指定／探测到的载体** → ③ **兜底 `instance/`，且必须告警**；运行态＝`_run/` |

## 五、★ 宿主侧持久代号（**2026-09-30 加 · 治「换宿主侦测过报」**）

**现象（真机实测）**：派生新会话读同一库 ⇒ 它**判了「换宿主」并写了事件账**，**看起来检测生效**；但对端自己点破了边界 —— **它运行时没有"持久保存自己的 `h_<uuid>`"** ⇒ 每个新会话只能**临时自造代号** ⇒ **恒定误报**「换宿主」，**永远无法确认"还是同一个宿主"**。

**⇒ 该做的（属适配层，**不动库**）**：**宿主侧把自己的代号存一次并持久化**（存在宿主自己的配置／记忆里）；读库时**自报并比对** `carrier.yaml` 的 `last_host` —— **一致** ⇒ 只更新 `last_seen`（**只读态除外**，见 `MANIFEST.md` §六 补充②）；**不一致** ⇒ 才写事件账。

> **口径：判据 ⑥ 拆两条** —— **(a) 结构可察觉**（比对逻辑 ＋ 事件账真的被执行）＝ **✅ 本宿主已证**；**(b) 判定准确**（同一宿主的连续访问**不被误判**）＝ **❌ 未达**，**根因在宿主侧、不在库侧**。
> **禁把「报了」当「测准了」。**

## 六、本宿主的坑（**2026-09-30 真机补录**）

| 坑 | 现象 | 处置 |
|---|---|---|
| **工作区外既有文件整写被拒** | 报 `stale_write_blocked: ... was last read with offset/limit pagination`，而文件实为**完整读取**（32／33／47 行小文件）；重读后再写**仍被拒** | 改用其 **`patch` 工具**即可正常落盘（**宿主侧行为，非我方可控**） |
| **`unzip -l` 中文名显示乱码** | 包内中文名显示为 `?`（如 `kernel-skeleton/01-??????`） | **非包缺陷** —— 实测 zip 内 **18 件非 ASCII 名的 UTF-8 标志位（`0x0800`）全置位** ⇒ 属**控制台代码页**；解压后文件名正确 |
| **`wmic logicaldisk` 静默无输出** | 该命令在本机兼容层下返回空 | 改用 PowerShell `Get-CimInstance Win32_LogicalDisk` 取 `DriveType` |
